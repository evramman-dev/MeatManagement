# دليل اختبار MeatManagement من المتصفح

## نطاق الاختبار الحالي

الاختبار يعمل على الموقع المنشور في GitHub Pages، ويستخدم حساب SYSTEM_TESTER فقط.

الاختبار للقراءة والتنقل فقط. لا ينشئ فواتير أو مشتريات أو إنتاجًا أو تحصيلات أو حركات مخزون، ولا يعدل بيانات التشغيل.

## إعداد بيانات الدخول

من مستودع MeatManagement افتح:

Settings
ثم Secrets and variables
ثم Actions

تأكد من وجود السرّين التاليين:

- TEST_USERNAME
- TEST_PASSWORD

لا تضع كلمة المرور داخل أي ملف، ولا ترسلها في المحادثات أو الصور.

## تشغيل الاختبار

1. افتح تبويب Actions.
2. اختر MeatManagement cloud browser tests.
3. اختر الفرع qa/full-cycle-test عند تشغيل Workflow.
4. اضغط Run workflow.

## ما الذي يفحصه الاختبار؟

- تسجيل الدخول بحساب المختبر.
- ظهور الرئيسية والمهام والبيانات.
- بقاء جلسة الدخول بعد إعادة تحميل الصفحة.
- ظهور الأقسام التي تسمح بها صلاحيات حساب المختبر فقط.
- عدم ظهور إدارة المستخدمين لحساب المختبر.
- فتح كل قسم مسموح والتقاط صورة له.
- تسجيل الخروج والعودة إلى شاشة الدخول.
- فحص واجهات Android بعرض 390 و360 بكسل.
- رصد التمرير الأفقي غير المقصود في الرئيسية والمهام والبيانات.
- أخطاء JavaScript غير المعالجة وأخطاء Console.
- فشل طلبات الشبكة وأخطاء HTTP من الموقع أو Supabase.

## النتائج

بعد انتهاء التشغيل افتح Artifacts ونزّل:

meatmanagement-browser-test-results

يحتوي الملف على الصور، وأثر الاختبار عند الفشل، وتقرير HTML عند توفره.

## حدود الاختبار

هذا ليس اختبارًا محاسبيًا أو اختبار دورة تشغيل كاملة. لا يثبت صحة القيود أو أرصدة المخزون أو تكلفة الإنتاج أو الصلاحيات لكل الأدوار.

اختبارات المعاملات تحتاج إلى بيئة اختبار معزولة وخطة تنظيف واضحة وموافقة مستقلة قبل إنشاء أي بيانات.


## مراجعة دورة الموردين الإضافية — 11 نوفمبر 2026

تمت مراجعة مسارات ملف المورد والسداد ومرتجعات المشتريات بعد نجاح اختبار كشف الحساب.

الإصلاحات على فرع QA:
- حفظ عنوان المورد مع بياناته، وإعادة تعبئته عند التعديل.
- إظهار أخطاء INSERT وUPDATE بدل إعلان نجاح الحفظ عند رفض قاعدة البيانات.
- إعادة ضبط نموذج المورد عند فتح نموذج مورد جديد.
- استبعاد السدادات الملغاة من سجل السداد وكشف حركة السدادات.
- استبعاد مرتجعات المشتريات الملغاة من سجل المرتجعات وكشف حركتها.
- تحسين منع تكرار سداد المورد: مفتاح مستقل لكل مستخدم، مع إنشاء request_id جديد إذا تغير المورد أو المبلغ أو التاريخ أو الخزنة أو الملاحظات. يبقى نفس المفتاح عند إعادة محاولة الطلب نفسه بعد انقطاع الاتصال.

لم يتم إنشاء أو تعديل أي سجل مالي. لم يتم تنفيذ سداد أو مرتجع أو فاتورة جديدة.

أضيفت اختبارات مصدرية آلية للتحقق من هذه الضوابط. وسيعمل اختبار المتصفح الحالي بعد تحديث فرع QA تلقائيًا.
