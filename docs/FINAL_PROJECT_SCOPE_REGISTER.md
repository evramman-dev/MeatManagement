# سجل نطاق النسخة النهائية - MeatManagement

تاريخ الإعداد: 2026-11-21
المرجع البرمجي: main / MeatManagement v163
الهدف: تثبيت نطاق النسخة المستهدفة قبل إضافة وظائف جديدة أو بدء اختبار الاعتماد النهائي.

## 1. قواعد إدارة النطاق

1. لا تُعاد اختبارات وظيفة اجتازت الاختبار ما لم يتغير كودها أو قاعدة بياناتها أو صلاحياتها أو تتأثر بتغيير آخر.
2. تختبر كل وحدة بعد تنفيذها، ثم تختبر نقاط التكامل المتأثرة فقط.
3. ينفذ اختبار تكامل نهائي واحد بعد إغلاق جميع الوحدات والقرارات.
4. لا يُعد ظهور الشاشة دليلًا على اكتمال الوظيفة. يجب إثبات الحفظ والصلاحيات والأثر المالي والمخزني عند انطباقها.
5. لا تنشأ جداول أو دوال أو صلاحيات موازية لوظائف موجودة.
6. أي تغيير في Supabase يحتاج موافقة صريحة على التغيير المحدد قبل التنفيذ.
7. لا تُدمج طلبات GitHub القديمة تلقائيًا. تُراجع فروقها مع main الحالي ويعاد تطبيق المطلوب فقط.
8. لا تُستخدم بيانات الإنتاج لاختبارات الكتابة. تستخدم حسابات وبيانات اختبار محددة، مع توثيق التنظيف أو العزل.
9. لا تُعلن النسخة نهائية قبل اكتمال اختبارات القبول الحرجة وتوثيق الاستثناءات المقبولة.
10. يظل النطاق مفتوحًا فقط لقرار جديد صريح أو عيب يمنع دورة تشغيل أساسية.

## 2. مرجع الحالة الحالية

- واجهة main الحالية هي v163.
- آخر دمج معروف للواجهة: PR #199.
- PR #200 مسودة منفصلة لقواعد تشغيل HR، غير مدمجة.
- لم تُجرَ في هذا السجل أي تغييرات على Supabase أو بيانات التشغيل.
- نجاح اختبارات سابقة لا يعني اكتمال اختبار شامل لكل وظائف التطبيق.
- لا توجد بيانات تشغيل فعلية كافية لإثبات جميع دورات العمل على بيئة إنتاج حقيقية.

## 3. سجل الوحدات الحالية

الحالات المستخدمة:
- موجود: الوظيفة أو المجال ظاهر في التطبيق أو قاعدة البيانات.
- موجود جزئيًا: توجد وظائف أساسية، لكن يلزم استكمال أو إثبات دورة فرعية.
- غير منفذ: لا توجد وحدة تطبيق مثبتة في النسخة الحالية.
- يحتاج قرارًا: لا يبدأ التنفيذ قبل قرار تشغيلي أو مالي.

## 4. قواعد منع التكرار والازدواج

- لا تُنشأ حركة مخزون بديلة عن stock_movements أو إجراءات المخزون الحالية.
- لا تُنشأ خزائن أو معاملات خزينة أو قيود محاسبية موازية.
- لا يُستخدم جدول المصروفات كبديل لتسوية التزام موظف أو سلفة راتب.
- لا تُنشأ دورة مرتجعات منفصلة عن sales_returns وفحص الاستلام الحالي.
- لا تُنشأ دورة نقل مستقلة عن trips وtrip_loads وحركات المخزون الحالية.
- لا تُنشأ قاعدة موظفين داخل app_users. ملف الموظف مستقل عن حساب الدخول.
- لا يُعامل sales_reps باعتباره سجل جميع الموظفين.
- لا يُحذف ملف الموظف تلقائيًا عند حذف حساب الدخول.
- لا تُكرر بيانات المورد أو العميل في وحدة خدمة العملاء أو الموردين الخارجيين إذا أمكن الربط بالسجل الأصلي.
- تحفظ سعات العبوات والتحويلات على مستوى المنتج، ولا تُعمم سعة طبق أو عبوة واحدة.

## 6. نطاق HR

ملف قواعد HR موجود في الفرع المرتبط بـ PR #200. لا توجد وحدة HR تنفيذية مثبتة في v163 ولا جداول HR مخصصة في مخطط Supabase الذي تمت مراجعته.

تسلسل التنفيذ المقترح:
1. اعتماد السياسات والقرارات التشغيلية.
2. تصميم الهيكل التنظيمي وملفات الموظفين.
3. تصميم الورديات والحضور والانصراف.
4. تصميم الإجازات والمأموريات.
5. تصميم الإضافي والجزاءات ومكونات الأجر.
6. تصميم السلف ومسيرات الرواتب والاعتماد.
7. تصميم انتهاء الخدمة والمخالصة.
8. التقارير والاختبارات والإطلاق.

بوابات إلزامية:
- اعتماد فصل ملف الموظف عن حساب الدخول.
- اعتماد صلاحيات الموظف والمدير المباشر وHR والحسابات والإدارة.
- اعتماد سياسة تسجيل الحضور والتصحيح والمأموريات.
- اعتماد مكونات الأجر والخصومات والسلف والأقساط.
- اعتماد دورة مراجعة واعتماد مسير الرواتب قبل الصرف.
- اعتماد الربط مع الخزينة والقيود الحالية دون إنشاء دورة مالية موازية.
- اعتماد سجل تدقيق يحفظ المنفذ والوقت والسبب والقيم السابقة واللاحقة.

لا تنشأ جداول أو صلاحيات HR قبل إغلاق القرارات ومراجعة التصميم مع المخطط الفعلي.

## 7. الإضافات التشغيلية غير المنفذة

يُعامل كل مجال أدناه كوحدة مستقلة لا يبدأ تنفيذها إلا بعد تحديد مالك العملية ومدخلاتها ومخرجاتها ونقاط اعتمادها وأثرها المالي أو المخزني.

### 7.1 تخطيط المشتريات وإعادة التوريد
- تحديد مصادر تقدير الاحتياج والرصيد المتاح والمحجوز والاحتياج الصافي.
- تحديد حدود إعادة الطلب ومخزون الأمان ومواعيد التوريد.
- تحديد مراجعة المورد والسعر وشروط الشراء.
- تحديد طلب الشراء والاعتماد والشراء العاجل والتوريد الجزئي والبدائل.
- منع اعتبار طلب الشراء فاتورة أو استلامًا أو حركة مخزون.

### 7.2 سلامة الغذاء
- ربط تحليل المخاطر بمراحل العملية والمنتج.
- تحديد نقاط التحكم الحرجة وحدودها ومسؤوليات المراقبة.
- تحديد الحجز والإفراج والتصرف في المنتج غير المطابق.
- اختبار التتبع والاستدعاء من المورد إلى العميل والعكس.
- منع تكرار سجلات التشغيلات والتتبع الحالية.

### 7.3 النظافة والتطهير ومكافحة الآفات
- تحديد المناطق ومستوى المخاطر وبرامج التنظيف.
- تسجيل المواد المستخدمة والتركيز ووقت التنفيذ والمسؤول.
- تسجيل التحقق والفشل وإعادة التنظيف والإجراءات التصحيحية.
- ربط النتائج بالموقع أو المعدة والوردية عند الحاجة.

### 7.4 المخلفات والمنتجات الثانوية
- اعتماد أنواع المخلفات والمنتجات الثانوية.
- تسجيل المصدر والوزن ووقت التجميع والحيازة.
- اعتماد النقل والتسليم والتخلص أو إعادة الاستفادة.
- تحديد المعالجة المالية عند البيع أو إعادة الاستخدام.

### 7.5 الطاقة والمياه والتبريد والمرافق
- تحديد نقاط القياس والعدادات ومصادر القراءة.
- تسجيل الاستهلاك والانقطاعات والأعطال.
- تحديد حدود الإنذار ومسؤول الاستجابة.
- ربط التكلفة بالفترة ومركز التكلفة عند اعتماده.

### 7.6 الصيانة
- تحديد الأصول والمعدات التي تحتاج سجل صيانة.
- تحديد الصيانة الوقائية والبلاغات والأوامر وقطع الغيار.
- تسجيل التوقف ووقت الإصلاح والاختبار قبل إعادة التشغيل.
- منع ازدواج سجل الأصل الحالي.

### 7.7 الموردون الخارجيون والعقود
- تحديد المورد الخارجي ومقدم الخدمة والعقد ونطاق العمل.
- تحديد التأهيل والاعتماد ومؤشرات مستوى الخدمة.
- توثيق الاستلام وعدم المطابقة والتجديد والإغلاق.
- فصل المورد الخارجي عن المورد الذي يورد أصناف المخزون إلا عند وجود علاقة واضحة.

### 7.8 خدمة العملاء والشكاوى التجارية
- تسجيل الشكوى والعميل والطلب أو الفاتورة المرتبطة.
- تحديد المسؤول والتحقيق والرد والتصعيد والتعويض.
- فصل الشكوى التجارية عن شكوى سلامة الغذاء.
- عدم إنشاء مرتجع أو تسوية مالية تلقائية من الشكوى دون مستند واعتماد مستقل.

## 8. اختبارات مفتوحة موثقة

### 8.1 الإنتاج
1. اختبار تحميل المصروفات المباشرة على تكلفة الإنتاج بعد مراجعة أنواع المصروفات وحساباتها المؤهلة.
2. اختبار قبول واجهة الإنتاج من حساب مستخدم تشغيلي فعلي.
3. اختبار المواد المسترجعة باستخدام منتجات تسمح بها سياسة الإنتاج، وعدم اختيار صنف غير مناسب لمجرد إكمال الاختبار.
4. اختبار ربط العبوات والملصقات بالمنتج النهائي وسعة العبوة والتحويل الخاص بالمنتج.
5. التحقق من دعم المنتجات نصف المصنعة كناتج مرحلة ومدخل مرحلة لاحقة وفق القواعد المعتمدة.

### 8.2 المشتريات والمبيعات والتقارير
1. مراجعة PR #100 ومطابقة أثر الاستبدال مع كشف العميل والقيود وحركة الصنف.
2. مراجعة PR #57 ومطابقة التخزين المبرد وتقسيم الأطباق مع المنتجات والتحويلات الحالية.
3. اختبار دورة شراء ومبيعات مترابطة على بيانات اختبار مع مطابقة الأرصدة والقيود.

### 8.3 الترحيلات
1. إعداد خريطة بين ملفات SQL المتاحة وسجل الترحيلات المسجل في Supabase.
2. تحديد الترحيلات المفقودة من المستودع دون إعادة تنفيذها.
3. توثيق الترحيلات التي لا يمكن استعادتها ومصدر التغيير إن أمكن.
4. إعداد طريقة استعادة مستقبلية موثوقة من الملفات المحفوظة.
5. لا تُعدّل سجلات schema_migrations ولا تنفذ ترحيلات تاريخية بغرض مطابقة الأعداد فقط.

## 10. استراتيجية الاختبار لتقليل التكرار

لكل تغيير يسجل:
- الوظيفة التي تغيرت.
- الملفات أو الدوال أو الجداول أو الصلاحيات المتأثرة.
- اختبارات الوحدة المطلوبة.
- اختبارات الانحدار المرتبطة بالتغيير.
- نتيجة الاختبار ومرجع التشغيل.
- هل يتطلب إعادة اختبار مسار متكامل أم لا.

قواعد إعادة الاختبار:
- تغيير نص أو تنسيق لا يعيد اختبارات الحسابات أو المخزون.
- تغيير شاشة دون تغيير منطق الحفظ يعيد اختبار العرض والإدخال والصلاحيات الخاصة بالشاشة.
- تغيير دالة مالية يعيد اختبار العملية والقيود والخزينة والتقارير المرتبطة بها.

- تغيير HR يعيد اختبارات HR والربط المالي أو التشغيلي المتأثر فقط.
- الاختبار النهائي يعيد المسارات الحرجة المترابطة بعد تجميد النطاق، ولا يعيد كل اختبار جزئي بلا سبب.
